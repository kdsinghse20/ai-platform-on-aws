================================================================================
                         TRAFFIC FLOW PATTERNS
================================================================================

INBOUND (Internet to OpenWebUI):
  User (external) → Route53 (DNS) → ALB (public)
  → Security Group allows 80, 443 from 0.0.0.0/0
  → Routed to OpenWebUI (10.0.10.x:80)

INTERNAL (OpenWebUI to Ollama):
  OpenWebUI (10.0.10.x) → Private subnets (local VPC routing)
  → Security Group allows 11434 from openwebui-sg
  → Routed to Ollama (10.0.20.x:11434)

OUTBOUND (Ollama to Internet, for model downloads):
  Ollama (10.0.20.x) → NAT Gateway #1 → IGW → Internet
  → External IP: NAT Gateway EIP
  → HTTPS (Port 443) to model registries

================================================================================
                         NETWORK SECURITY LAYERS
================================================================================

LAYER 1: VPC
  • Private subnets prevent direct internet access
  • NAT Gateways control outbound traffic
  • No direct routing from compute to internet

LAYER 2: Internet Gateway & NAT Gateway
  • IGW: Only in public subnets
  • NAT: Translates private IPs to EIP
  • Stateful: Responses allowed back

LAYER 3: Security Groups (Firewall)
  • ALB-SG: Allow 80/443 from 0.0.0.0/0
  • OpenWebUI-SG: Allow 80 from ALB-SG, 11434 out to Ollama-SG
  • Ollama-SG: Allow 11434 from OpenWebUI-SG, 443 out to internet
  • Default deny all (implicit)

LAYER 4: Network ACLs (Stateless, optional)
  • Not configured (using defaults)
  • Could add for additional control
